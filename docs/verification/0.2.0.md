# Version 0.2.0 verification

Rice Accounts switches Anthropic OAuth accounts within one session. Additional
account folders supply authentication and identity metadata. They do not replace
the session's machine configuration, selected model, plugins, skills or MCP setup.

TypeScript checking passed against the generated native 2.1.299 API declarations
with strict mode and unchecked indexed access enabled. Actual native validation
and execution on the hosts above establish runtime compatibility.

On WSL, the first source transfer contained macOS resource metadata. That setup
failure was corrected before the successful runtime checks. The final WSL
canonical command reached a staged whitespace failure after every runtime check
passed. Removing extra terminal blank lines in two test files and checking the
corrected files with native WSL Git closed that failure without replaying the
successful runtime proof.

## Acceptance scope

- Adding an account defaults to `claudeai`. Repeating add or setup preserves its
  saved configuration and prints the terminal helper command again.
- The helper isolates Claude authentication, handles prerequisite failures and
  interrupted login, and verifies local readiness. Setup tokens use a hidden
  terminal prompt and the operating system keyring.
- Only machine login, separate Claude sign-ins and Claude OAuth setup tokens are
  selectable. Older provider entries survive ordinary OAuth configuration edits
  and cannot trigger credential access or account switching here.
- The native picker renders account names, email, plan and the current marker.
  Buttons and keyboard selection use the production switch callback. Cancellation
  leaves authentication unchanged; failures remain visible. Headless sessions
  receive the text list. Unknown identity or plan is shown explicitly.
- Linux credential reads reject symbolic links and malformed records. Refresh
  writes check the expected grant, preserve unrelated current fields and replace
  the native credential file atomically with mode `0600`.
- Switching from account A to B and then to `login` restores the process's
  original credential environment. Configuration directory variables and files
  remain unchanged. Isolated account settings files are never loaded.
- Real native processes verify a subagent, both process APIs, Bash and native
  `claude -p` descendants inherit the selected account. A simultaneous sibling
  stays unchanged and a new independent process keeps its launch account.
- Every native process path retains the machine configuration directory, a
  machine settings marker and the machine's actual model despite contradictory
  settings in the account folders.
- Failed child authentication preparation refuses execution instead of falling
  through to a child with an unintended account.

## Native integration proof

`scripts/proof-session-processes.mjs` creates an isolated plugin copy, HOME and
configuration, and owns every process it starts. Authentication reads and model
replies are synthetic. Environment mutation, native subagents, shell execution,
child processes and simultaneous sessions are real. No user account, installed
plugin or live inference is used.

The proof invokes the unmodified production command function from its test
handler because the native API refuses slash-command scheduling inside a turn
hook. Separate native tests exercise actual command dispatch.

Native Claude deliberately filters OAuth tokens from child environments. The
mod forwards the selected token through explicit process environments and a
static Bash reference to an environment relay. Credential bytes are absent from
generated command text. The relay is derived process state and does not change
the user's settings files. There is no inference proxy or listener.

Run the canonical checks from the repository root:

```sh
npm run check
```

Browser authentication and live subscription entitlements require the account
owner's sign-in. These isolated checks do not claim to exercise paid provider
inference or every account's permissions. Cached plan labels describe saved
metadata; they do not replace provider authorization.
